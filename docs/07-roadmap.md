# 07. フェーズ分けと構築見積り

## フェーズ0 — 作る（完了）

**成果物**: `packages/generator`

- テンプレートDSL（`$switch` / `$ref` / 文字列補間）
- 直交配列によるバリアント選択と決定論的な `creative_id` 採番
- 日本語組版（禁則処理・自動縮小・帯・縁取り）と3アスペクト比の解決
- Ken Burns / トランジション / オーバーレイ / BGM の合成
- セーフエリア検証（インストリーム／Shorts）
- 決定タグの manifest / CSV 出力
- 社内レビュー用の静的ページ

**動作確認済み**: サンプル素材から 6パターン × 3比率 = 18本を生成（4コアで約8分）。

**この時点でできること**: 素材とコピーを差し替えれば、毎月30クリエイティブを1コマンドで出せます。
入稿と分析は手動ですが、**「作る」のボトルネックはこの時点で解消しています。**

## フェーズ1 — 計測の土台（4〜6週）

分析を始めるにはデータが要るので、まず配管を通します。

| 作業 | 内容 | 目安 |
|---|---|---|
| Warehouse 構築 | Postgres、`docs/05-dashboard.md` のスキーマ | 3日 |
| manifest 取り込み | `out/creatives.csv` → `creatives` テーブル | 2日 |
| Google Ads API 連携 | OAuth、日次取得、`creative_id` 突合、異常検知 | 8日 |
| YouTube Analytics 連携 | 秒単位の維持率取得 | 4日 |
| LLM Tagger | フレーム抽出＋Structured Output＋保存 | 5日 |
| ジョブ基盤 | cron、冪等性、リトライ、Slack通知 | 3日 |

**前提**: Google Ads API の開発者トークン（本番）の申請。審査に2〜4週かかることがあるので、
**着手前に出しておいてください。** ここが最長のリードタイムです。

**この時点でできること**: 「どの要素の動画がどれだけ回ったか」がSQLで引けます。
まだダッシュボードは無く、分析は手動クエリです。

## フェーズ3 — 磨き込み（随時）

優先度順。フェーズ2までが回ってから、実データを見て判断するのが妥当です。

| 項目 | 内容 | 効果 |
|---|---|---|
| テンプレート追加 | 月1本ペース。UGC風、比較表、証言型など | 検証できる型が増える |
| AI動画フックの差し込み | `scenes[].asset` を動画クリップ対応に拡張 | 冒頭の表現幅 |
| コピー生成の自動化 | 決定タグ×実績を踏まえてLLMがコピー案を出す | W1の工数削減 |
| Google Ads 自動入稿 | 一時停止状態まで作り、有効化は人が承認 | W3の工数削減 |
| レンダリングのクラウド化 | ジョブキュー化 | 本数が3倍を超えたら |

**Google Ads 自動入稿を後ろに置いている理由**は `docs/01-architecture.md` に書いたとおりで、
月30本規模では投資対効果が合わず、誤配信リスクだけが増えるためです。
本数が月100本を超えたら再検討する、という判断でよいと思います。

## 見積りまとめ

| フェーズ | 期間 | 内容 |
|---|---|---|
| 0（完了） | — | 作る |
| 1 | 4〜6週 | 計測の土台 |
| 2 | 5〜7週 | 示唆とダッシュボード |
| **合計** | **9〜13週** | 一周する状態まで |

同時進行で運用は始められます。フェーズ0が終わっている今、
**来月ぶんの30クリエイティブは今日から作れます。**
その間に貯まる実績が、フェーズ1完了時点の初回分析の材料になるので、
「作る」を先に走らせておくのが合理的です。

### 並行して進めておくこと

- [ ] Google Ads API 開発者トークンの申請（**最優先。リードタイムが最長**）
- [ ] Google Cloud プロジェクトと OAuth クライアントの用意
- [ ] クライアントとの素材受け渡しフロー（Driveの共有フォルダ構成）
- [ ] コピーの表記チェック体制（景表法・社内基準）
- [ ] ダッシュボードのホスティング先の決定

## リスクと対処

| リスク | 影響 | 対処 |
|---|---|---|
| Ads API トークン審査の遅れ | フェーズ1が止まる | 先に申請。当面はUIからのCSVエクスポートで代替 |
| `creative_id` の入れ忘れ | 分析から静かに抜け落ちる | 異常検知を必ず作り、ダッシュボードに出す |
| 本数が少なく示唆が出ない | 判断が止まる | パターン数を増やす（人の工数は増えない）。表記基準で断定を防ぐ |
| 自動最適化による配信の偏り | タグ比較が歪む | 均等配信の検証用キャンペーンを別に切る |
| テンプレートが1つだけ | 型の比較ができない | フェーズ2までに3〜4型に増やす |
| 素材の権利期限切れ | 配信停止 | `project.json` に利用期限を持たせ、期限前に警告する（未実装・小規模な追加） |
