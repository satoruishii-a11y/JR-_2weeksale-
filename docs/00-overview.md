# 00. 全体像と技術選定の理由

## この仕組みが解こうとしていること

静止画素材を起点に、YouTube広告のクリエイティブを **作る → 配信する → 分析する** の3ステップで
月次で回し続ける。分析結果が次の制作パラメータに戻ることで、続けるほど当たる確率が上がる状態を作る。

```
月5本の企画  ──▶  1本あたり6パターン  ──▶  月30クリエイティブ  ──▶  タグ×実績で示唆  ──┐
     ▲                                                                            │
     └────────────────  次月のテンプレート・軸・コピーに反映  ◀──────────────────────┘
```

---

## 「簡易だが他社と類似しない」をどう成立させるか

いただいた質問への回答です。結論は **FFmpegベースの自前レンダラーを土台にする** で、
理由は「似る/似ない」を決めているのが生成技術ではなく**テンプレートの出所**だからです。

### 3方式の比較

| | Canva Connect API | 生成AI動画（Veo等） | FFmpeg自前レンダラー |
|---|---|---|---|
| 他社との被り | **最も被る**。既製テンプレは世界中の広告主が同じものを使う | 被りにくい | **構造的に被らない**。テンプレートが自社にしか存在しない |
| 毎月の作業量 | 素材流し込み＋書き出し | プロンプト試行が毎回発生 | **素材とコピーの差し替えのみ** |
| 1素材からのパターン量産 | 手動に近い | コストが本数に比例 | **1コマンドでN本** |
| 尺・文字・被写体の制御 | 高い | **低い**（同じ品質で毎月出すのが難しい） | 完全に制御できる |
| 再現性（同じ入力→同じ出力） | 概ねあり | **無い** | **完全にある** |
| 初期構築 | API申請＋テンプレ作成 | 少ない | **テンプレート設計が要る（今回実施済み）** |
| ランニング費用 | Canvaプラン | 生成従量課金 | **ゼロ** |

### 「簡易」の意味を分けて考える

- **初回の簡易さ**: 生成AI動画が有利。プロンプトを書けば出る。
- **2回目以降の簡易さ**: 自前レンダラーが圧倒的に有利。`project.json` の素材パスとコピーを
  差し替えて1コマンド実行するだけで、次の月の30本が出る。

月5本を**恒常的に**回したいという要件なので、効くのは後者です。
初回のテンプレート設計コストは1回きりで、以降は資産として効き続けます。

### 「他社と類似しない」の源泉は3つある

1. **テンプレートが自社資産である**こと（初月から効く）
   `templates/*.json` はカット割り・モーション・タイポグラフィ・時間設計をコード化したものです。
   これは他社が持っていないので、同じ素材を使っても出てくる絵が違います。
2. **組み合わせ空間**（初月から効く）
   軸（フック × テロップ表現 × CTAタイミング）× 素材 × コピーの掛け算で、
   毎月まったく同じ絵にはなりません。今回のテンプレートで 3×2×2 = 12通り。
3. **分析ループによる自社最適化**（3〜6ヶ月で効いてくる）
   「自社の顧客に効く型」に寄っていくため、他社の平均から離れていきます。
   ここが本命で、1と2はそこに至るための土台です。

### 生成AI動画をどう位置づけるか

否定はしません。ただし「全編をAIで作る」のではなく **冒頭2〜3秒のフックだけ差し込む** 使い方が
費用対効果が高いと考えています。離脱が集中するのは冒頭で、そこだけ表現の幅が要るためです。

テンプレートDSLの `scenes[].asset` は画像を指しますが、ここを動画クリップに拡張すれば
差し込み口になります。今回は実装していません（フェーズ2、`docs/07-roadmap.md` 参照）。

## 「タグ付けはLLM側でやればよく、生成時点では不要」について

半分そのとおりで、半分だけ補足させてください。

### LLMが正しく担うもの ＝ 知覚タグ

訴求軸、感情トーン、被写体の印象、冒頭の情報密度、ブランド想起、表現リスク。
これらは完成した動画を見ないと分からないので、LLMに任せるのが正解です。

### 生成器が既に知っているもの ＝ 決定タグ

尺、カット数、平均ショット長、モーション種別、テロップ文字数、最大フォントサイズ、
CTAが何秒地点で出るか、使用素材、アスペクト比 ——
これらは**レンダラーが計算に使った値そのもの**です。

ここが要点で、**これをJSONに書き出すのは生成時の追加作業ではありません**。
すでにメモリ上にある値をファイルに落とすだけなので、工数はゼロです。
実装済みで、`out/manifests/<creative_id>.json` に自動で出ます。

### なぜ両方持つのか

LLMだけだと、示唆が「テンポが速いものが良さそう」で止まります。
決定タグがあると「平均ショット長2.1秒以下の群がVTR+3.2pt」となり、
**次のテンプレートの `duration` に直接書き戻せます**。

| | 決定タグ | 知覚タグ（LLM） |
|---|---|---|
| 出どころ | レンダラー | 完成動画をLLMが分解 |
| 正確さ | 誤りなし・欠損なし | 推論なのでブレる |
| 追加コスト | ゼロ | API費用と処理時間 |
| 使い道 | **次の生成パラメータに直結** | 意味レベルの解釈・言語化 |

詳細は `docs/03-tag-taxonomy.md`。

## 一番重要な設計判断：月5本を月30クリエイティブにする

タグ×実績の分析は、月5本では統計的に成立しません。5本で6タグを比較すると
1タグあたり1本を下回り、どんな差も偶然と区別がつきません。

一方、**1本の企画を6パターンに割る**と月30クリエイティブになります。

- 素材の追加撮影は不要（同じ静止画を使い回す）
- 制作の追加工数はほぼゼロ（レンダリング時間が増えるだけ）
- 学習に使えるサンプルが6倍

半年で180クリエイティブ、1年で360。この規模になって初めてタグ分析が意味を持ちます。
**「作る」を自動化する最大の理由は、量産そのものではなく分析を成立させることです。**

さらに、パターンの選び方も効きます。全数の中からランダムに6本選ぶと
「速いテンポの動画はたまたま全部黄色いテロップだった」という偏りが混入し、
どちらが効いたのか分離できません。実装では**直交配列**で選んでいるので、
各軸の各値が均等に出ます（`docs/04-analysis.md` の交絡の項）。

```
$ creative-gen plan --project projects/sample-2weeksale --template hook-price --strategy orthogonal:6

軸 ctaTiming
   early            ■■■ 3
   late             ■■■ 3
軸 hook
   price            ■■ 2
   scarcity         ■■ 2
   question         ■■ 2
軸 textStyle
   clean            ■■■ 3
   impact           ■■■ 3
```
