# 06. 月次運用フロー

## 月次カレンダー

想定は「月5企画 × 6パターン × 3アスペクト比 ＝ 月90ファイル（30クリエイティブ）」です。
本数が多く見えますが、人が判断するのは**企画5本ぶんだけ**です。

| 週 | やること | 担当 | 目安 |
|---|---|---|---|
| **W1** | 前月の示唆レビュー → 今月の企画5本を決める | プランナー＋自社 | 2h |
| | 素材の選定・受領（クライアントのDriveから） | 制作 | 2h |
| | コピー案の作成（LLMで20案→3案に絞る） | プランナー | 2h |
| | `project.json` の更新（素材パス・コピー・ブランド色） | 制作 | 1h |
| | `creative-gen layout` で組版チェック → コピー調整 | 制作 | 0.5h |
| **W2** | `creative-gen render` で一括生成 | 制作 | 実行1〜2h（待つだけ）|
| | `out/index.html` で社内レビュー → 差し戻し・再生成 | 自社 | 2h |
| | クライアント確認 | — | 1h |
| **W3** | YouTube へアップロード（タイトルに `creative_id`） | 運用 | 1.5h |
| | Google Ads へ入稿（アセット名に `creative_id`） | 運用 | 1.5h |
| | 配信開始・初期チェック | 運用 | 0.5h |
| **W4** | 中間確認。明確な負けを停止 | 運用 | 1h |
| | ダッシュボードで異常検知（ID入れ忘れ・入稿漏れ）を確認 | 運用 | 0.5h |
| **翌W1** | 月次サマリーの確認 → テンプレート更新 → 次月企画へ | 全員 | 2h |

**月の合計は概ね 20〜22時間。** うち機械が動いている待ち時間が2時間前後です。

## 各ステップの具体的な手順

### W1: 組版チェックまで

```bash
cd packages/generator

# 1) 素材を置く
#    projects/<案件>/assets/ に静止画・ロゴ・BGM を配置

# 2) project.json のコピーと素材を差し替える

# 3) 設定と素材の存在チェック
npx tsx src/cli.ts validate --project projects/<案件> --template hook-price

# 4) 何本どう振られるかを確認
npx tsx src/cli.ts plan --project projects/<案件> --template hook-price --strategy orthogonal:6

# 5) 組版チェック（ffmpeg を回さないので数秒）
npx tsx src/cli.ts layout --project projects/<案件> --template hook-price \
  --strategy orthogonal:6 --ratios 9x16,16x9,1x1
```

**5 が重要です。** ここで
「コピーが長すぎて自動縮小の下限に当たった」「テロップがUIに隠れる位置にある」
が出るので、レンダリング前にコピーを直せます。ここを飛ばすと、
2時間かけて描画したあとで作り直しになります。

### W2: 生成とレビュー

```bash
npx tsx src/cli.ts render --project projects/<案件> --template hook-price \
  --strategy orthogonal:6 --ratios 9x16,16x9,1x1 --contact-sheet

# 出力
#   out/videos/<creative_id>.mp4     入稿するファイル
#   out/videos/<creative_id>.jpg     サムネイル
#   out/manifests/<creative_id>.json 決定タグ
#   out/creatives.csv                取り込み用
#   out/index.html                   社内レビュー用
```

`out/index.html` をブラウザで開くとパターンが並び、軸でフィルタできます。
差し戻しがあればテンプレートかコピーを直して再実行します。
**同じ入力からは同じ動画が出るので、直していない部分は前回と完全に同一です。**

### W3: 入稿

守るルールは1つだけ。**動画タイトルとアセット名に `creative_id` を入れること。**

```
YouTube 動画タイトル : 2週間セール_縦_A ［sample-2wk_hook-price_08de3b_9x16］
Google Ads アセット名 : sample-2wk_hook-price_08de3b_9x16
```

これで実績と決定タグが自動で突き合わさります（`docs/02-creative-id.md`）。

## 役割分担

| 役割 | 責任 |
|---|---|
| プランナー | 企画・コピー・示唆の解釈 |
| 制作 | 素材整備・`project.json` 更新・生成・組版チェック |
| 運用 | 入稿・配信管理・停止判断 |
| エンジニア | テンプレート追加・パイプライン保守（定常では月2〜4h） |

**テンプレートの新規作成だけはエンジニアの仕事**です（月1本ペースが目安）。
既存テンプレートの軸の値を足す・減らすは JSON の編集なので、制作でも触れます。

## チェックリスト

### 生成前
- [ ] 素材の使用許諾・期限を確認した
- [ ] コピーの表記チェックを通した（景表法・社内基準）
- [ ] `validate` が通る
- [ ] `layout` で警告ゼロ（`safe-area` / `text-overflow`）
- [ ] `plan` の軸配分が均等になっている

### 入稿前
- [ ] `out/index.html` で全パターンを再生確認した
- [ ] 尺が枠の要件に合っている（バンパーは6秒未満）
- [ ] 音量が過大でない
- [ ] クライアント確認済み

### 入稿後
- [ ] すべての動画タイトル・アセット名に `creative_id` が入っている
- [ ] ダッシュボードの異常検知がゼロ
- [ ] 配信開始から3日は成績で判断しない（学習期間）

## 増やすとき / 減らすとき

| 状況 | 対応 |
|---|---|
| パターンを増やしたい | `--strategy orthogonal:12` に変える。人の工数は増えない |
| 検証したい仮説が増えた | テンプレートに軸を1つ足す。本数は `orthogonal:N` で固定できる |
| 縦だけで十分 | `--ratios 9x16` にする。レンダリング時間が1/3になる |
| 企画本数を減らしたい | 企画3本 × 10パターンでも月30。**分析の観点では等価** |
| 急ぎで下書きが要る | `--preset veryfast --ratios 9x16` で確認用を先に出す |

---

## レンダリング時間の目安

4コアのマシンでの実測（15秒・1080×1920・4カット・6オーバーレイ）:

| 条件 | 1本あたり | 18本（6パターン×3比率） |
|---|---|---|
| `--preset medium`（納品品質） | 約100秒 | 約12分（並列3） |
| `--preset veryfast`（下書き） | 約75秒 | 約9分（並列3） |

CPUコアを増やせばほぼ線形に短くなります。月1回の処理なので、
専用サーバーを立てるほどではありません。作業マシンで昼休みに回す程度で足ります。
