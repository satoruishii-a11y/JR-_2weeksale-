# 04. 分析と示唆出しの設計

## 目的をはっきりさせる

このステップの成果物は「レポート」ではなく **次月の制作指示** です。
「テンポが速いほうが良さそうです」で終わらせず、
`templates/hook-price.json` の `duration` をいくつにするか、
`axes.hook` からどの値を落とすかまで落ちて初めて、ループが閉じます。

---

## 取得する指標

### Google Ads API（動画キャンペーン）

| 指標 | 何を読むか |
|---|---|
| `impressions` | 配信量。**タグ比較の前に必ず揃っているか確認する** |
| `views` / `video_view_rate` | 一次的な引きの強さ |
| `video_quartile_p25/50/75/100_rate` | どこで離脱したか（粗い解像度） |
| `average_cpv` | 効率 |
| `clicks` / `ctr` | 行動喚起の強さ |
| `conversions` / `cost_per_conversion` | 最終成果 |
| `cost` | 予算配分の偏りチェック |

### YouTube Analytics API

| 指標 | 何を読むか |
|---|---|
| `audienceWatchRatio`（秒単位） | **冒頭何秒で落ちたか**。四分位より遥かに解像度が高い |
| `relativeRetentionPerformance` | 同種動画との相対比較 |

秒単位の維持率カーブが、この仕組みで最も価値のあるデータです。
`first3s_text_chars`（決定タグ）や `hook_device`（知覚タグ）と突き合わせると、
「冒頭に文字を詰めすぎると2秒地点で落ちる」といった**次に直せる形の示唆**が出ます。

## LLM分解パイプライン

```
out/videos/<creative_id>.mp4
   │
   ├─ ffmpeg: 0.5秒ごとにフレーム抽出（冒頭3秒は0.25秒ごと）
   ├─ ffmpeg: コンタクトシート（生成時に出力済み）
   ├─ （任意）音声書き起こし
   └─ manifest.json の決定タグ
        │
        ▼
   LLM（Structured Output / JSON Schema 強制 / temperature 0）
        │
        ▼
   creative_perception テーブル（1クリエイティブ1行）
```

- **1クリエイティブにつき1回だけ実行し、結果を固定します。** 再実行すると出力が微妙に揺れ、
  過去の集計値が変わってしまいます。
- 決定タグを一緒に渡し、**尺・カット数・文字数はLLMに数えさせません**。
- `evidence`（根拠の抜粋）を必須項目にして、人が検算できる状態にします。

## 結合

```sql
SELECT
  c.creative_id,
  c.hook_type, c.pacing, c.first3s_text_chars, c.cta_position_ratio,   -- 決定タグ
  p.appeal, p.hook_device, p.tone, p.text_readability,                 -- 知覚タグ
  SUM(m.impressions) AS impressions,
  SAFE_DIVIDE(SUM(m.views), SUM(m.impressions)) AS view_rate,
  SAFE_DIVIDE(SUM(m.cost), SUM(m.views))        AS cpv,
  SUM(m.conversions)                            AS conversions
FROM creatives c
LEFT JOIN creative_perception p USING (creative_id)
JOIN creative_metrics m         USING (creative_id)
WHERE m.date BETWEEN @from AND @to
GROUP BY 1,2,3,4,5,6,7,8,9
```

## タグの効き目をどう出すか

### 基本形：含む群 vs 含まない群

タグ `T` について、`T` を持つクリエイティブ群と持たない群で指標を比べ、
差と信頼区間を出します。

```
効果量(T) = mean(VTR | T=あり) − mean(VTR | T=なし)
```

### そのままでは誤読する。3つの補正が要る

#### ① 交絡 — 生成側で潰す

「テンポが速い動画はたまたま全部黄色いテロップだった」という状態だと、
テンポと配色のどちらが効いたか永久に分かりません。

**これは分析では直せないので、生成側で潰します。**
`orthogonal:N` は各軸の各値が均等に、かつ2軸の組み合わせも広く覆うようにパターンを選びます。

```
$ creative-gen plan --template hook-price --strategy orthogonal:6
軸 hook       price:2  scarcity:2  question:2
軸 textStyle  clean:3  impact:3
軸 ctaTiming  early:3  late:3
```

この配分だと、`hook=price` の群と `hook=scarcity` の群で
textStyle と ctaTiming の内訳がほぼ揃うので、差を hook に帰属させられます。
**設計時点で分析可能性を作り込んでおくのが、この仕組みの肝です。**

#### ② 配信量の偏り — 予算が結果を作ってしまう

Google 側の自動最適化が特定のクリエイティブに配信を寄せると、
「よく配信されたから成果が多い」だけの動画が勝って見えます。

対策：
- 検証期間中は**均等配信のキャンペーンを別に切る**（推奨。予算の1〜2割で足りる）
- それが難しい場合は、比率指標（VTR、CPV、CVR）だけで比較し、絶対値では比較しない
- `impressions` が全体の中央値の 1/3 未満のクリエイティブは分析から外す

#### ③ サンプル数 — 断定させない仕組みを入れる

月30本でも、3値の軸なら1値あたり10本です。差が偶然かどうかは慎重に扱う必要があります。

**表記を機械的に強制します。**

| クリエイティブ数 | 累計表示回数 | 表記 |
|---|---|---|
| n < 6 | — | 「参考値」。示唆を出さない |
| 6 ≤ n < 12 | 10万未満 | 「傾向」。断定表現を禁止 |
| n ≥ 12 | 10万以上 | 「示唆」。信頼区間を併記 |
| 累計3ヶ月以上 | — | 「知見」。テンプレート標準への反映を検討 |

これはダッシュボードの表示ロジックと、示唆生成LLMのプロンプト制約の両方に入れます。
**人間が言葉を選ぶ運用に頼らず、データ量から表記が決まるようにします。**

### 冒頭離脱の分析（最も価値が出るところ）

```
維持率カーブ（秒単位） × 冒頭の決定タグ
```

見るのは主に3つです。

1. **2秒地点の残存率** — フックが効いたかの単一指標。`hook_device` 別に比較
2. **カーブの折れ点** — 全クリエイティブ共通で落ちる秒があれば、それは尺構成の問題
3. **`first3s_text_chars` との相関** — 文字を詰めるほど落ちるのか、逆なのか

## 示唆の出し方

集計はSQLで確定させ、**LLMには「数値の言語化と優先順位付け」だけをさせます**。
LLMに集計させると数字が合わなくなります。

### 出力フォーマット（固定）

```markdown
## 今月の結論
（1〜2文。次に何を変えるか）

## 根拠になった数字
| 軸 | 値 | 本数 | VTR | CPV | 全体との差 | 判定 |
|---|---|---|---|---|---|---|
| hook | price | 10 | 34.2% | ¥5.1 | +3.8pt | 示唆 |
| hook | question | 10 | 28.1% | ¥6.4 | −2.3pt | 傾向 |

## 次月の制作パラメータ
- `axes.hook` から `question` を外し、`price` と `scarcity` に絞る
- `hook-price.json` の scenes[0].duration を 4.2 → 3.4 に短縮（2秒地点の離脱が想定より早い）
- 新しい軸 `subjectType`（人物あり／風景のみ）を追加して検証

## 判断を保留したもの
- textStyle: 差 +0.9pt、本数15。誤差の範囲。来月も同条件で継続
```

**「判断を保留したもの」を必ず書かせる**のが重要です。
これが無いと、すべての軸に無理やり結論が付き、翌月のテンプレートが根拠なく揺れます。

### 生成へのフィードバック

示唆はテンプレートJSONへの具体的な変更として書き戻します。

| 示唆の種類 | 反映先 |
|---|---|
| 特定の軸の値が弱い | `axes.<name>.values` から削除 |
| 尺・テンポ | `scenes[].duration` |
| CTAのタイミング | `axes.ctaTiming` の値、または固定値に |
| 被写体 | `project.assets` の選定基準（次の撮影発注） |
| 新しい仮説 | 新しい軸を追加。または新テンプレートを起こす |

テンプレートを実質変更したら `version` を上げます。
`variant_hash` が変わるので、変更前後が混ざらずに済みます。

## よくある誤読

| 誤読 | 実際 |
|---|---|
| 配信初日から成績が悪いので止める | 学習期間中。最低3〜5日、または表示1万回までは判断しない |
| VTRが高いクリエイティブが最良 | VTRは引きの強さ。CVと逆行することがある（煽り系に多い） |
| 縦動画のほうが成績が良い | 面が違うだけ。`aspect_ratio` をまたいだ比較はしない |
| 先月効いた型が今月も効く | 季節・在庫・競合で変わる。3ヶ月連続で再現したものだけ「知見」に昇格 |
| 勝ちパターンに寄せ切る | 全部同じ型にすると学習が止まる。**毎月2割は新しい軸の検証に使う** |
